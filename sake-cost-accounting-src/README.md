# 酒造原価管理システム PoC

公開中の画面構成を維持しつつ、現行Excelと並行計算できる状態を目指して再構成した、単一端末・単一利用者向けのReact/Vite実証版です。配賦、工程別原価、食品差額、棚卸資産、売上原価、年度確定の入力統制をブラウザ内で検証できます。

これは本番システムではありません。認証、権限、複数人同時編集、データベース、サーバーバックアップ、承認ワークフロー、完全な監査証跡、実CSVの正式マッピングは未実装です。公開URLには実在企業名、担当者名、実金額、顧客データを入力しないでください。

## ソースと公開物

- 保守対象ソース: `sake-cost-accounting-src/`
- GitHub Pages公開物: `../sake-cost-accounting-mockup/`
- Vite base: `/staff-portal/sake-cost-accounting-mockup/`
- 元の保守可能なソースはリポジトリ・関連作業領域・履歴から見つからなかったため、公開デモの画面構成を基準に本プロジェクトを再構成しています。
- `sake-cost-accounting-mockup/assets/` の圧縮済みファイルは直接編集せず、必ず本ソースから再生成します。

## 起動・検証

Windowsでは次のコマンドを使用します。

```powershell
npm.cmd ci
npm.cmd run dev
npm.cmd run lint
npm.cmd test
npm.cmd run build
npm.cmd run verify:pages
npm.cmd run test:e2e -- --reporter=dot
```

`npm.cmd run build` は型検査後、公開物を `../sake-cost-accounting-mockup/` へ出力します。`npm.cmd run verify:pages` はHTMLが参照するJS/CSS、公開base path、未参照の旧資産、`noindex,nofollow,noarchive`、生成物の未ステージ差分・未追跡ファイルを検査します。GitHub Pagesへ反映する場合は、生成物を含むブランチをレビュー・マージし、Pagesワークフロー完了後に公開URLを直接再読み込みしてJS/CSSの404と表示内容を確認します。

Pull Requestと`main`へのソース・公開物の変更では、`.github/workflows/sake-cost-accounting-ci.yml`がNode.js 24で`npm ci`、lint、単体・コンポーネントテスト、ビルド、Pages成果物整合性確認、Chromium E2Eを自動実行します。ローカルでも上記コマンドを同じ順序で実行できます。

## データ保存

- localStorageキー: `sake-cost-accounting-public-demo-v2`
- JSONスキーマ: `schemaVersion: 3`（localStorageキー名のv2は既存データ継承のため維持）
- v1/v2の金額・数量・行を可能な限り保持し、`active` を `allocationEligible` へ、旧アルコール度数を後方互換用の未使用項目へ移行します。v2の副産物には内部払出0円・財務集計対象を補います。
- 不正JSON、未対応スキーマ、必要項目が欠けたデータは拒否し、復元前には確認ダイアログを表示します。
- UIで負数を許可していない数量・金額・単価・比率を含むJSONも拒否し、失敗時は現在データを変更しません。材料の振替・調整、原酒の振替数量・金額、商品の期首調整だけは負数を許可します。
- 確定時の入力と主要結果は最大10件の読み取り専用スナップショットとしてJSONに保存します。履歴自身は再帰的に含めません。
- 起動時に保存データを解析・移行できない場合は通常画面を開かず、復旧画面へ移行します。元のlocalStorage文字列は削除・上書きせず、自動保存も開始しません。
- 復旧画面の「復旧用データを保存」は、解析不能な内容を含め元文字列を変更せず`.txt`へ保存します。rawデータ全文は画面に表示しません。
- 「正常デモで初期化」は確認ダイアログ後の明示操作です。可能な場合は元文字列を日時付きリカバリーキーへ退避してから元キーを置き換え、操作履歴へ記録します。退避に失敗した場合は元キーを変更せず、別の確認を経た場合だけ退避なしで続行できます。
- localStorage自体を読み取れない場合は正常デモをメモリ上だけで開き、常時「このセッションは自動保存されません」と表示します。JSON保存は利用できます。

localStorage、JSON、入力ハッシュはクライアント側の利便機能であり、改ざん防止や耐障害バックアップを保証しません。ブラウザ初期化・端末故障に備えてJSONを別媒体へ保存してください。

## 計算と確定の要点

- 金額は整数円、数量・比率は小数第3位で丸めます。入力中は`10.`のような途中状態を保持し、全角数字・全角小数点を正規化して、blurまたはEnterで確定します。
- 共通費は対象酒種だけに最大剰余法で決定論的に配賦します。分母ゼロ、対象ゼロ、対象外入力、直課超過、個別入力不一致はエラーです。
- 詰口製品の売上原価数量・金額から評価損・欠減を控除します。
- 副産物は内部払出金額を控除でき、米麹のような内部利用品を副産物売上原価・期末棚卸の合計対象外にできます。ただし財務集計対象外の行に期首・発生・購入・内部払出・期末の金額が残る場合、内部振替先が未確定のため計算エラーとして年度確定を停止します。推測による自動振替は実装していません。
- 食品製造原価と食品別製造金額は自動配賦せず、差額0円を必須にします。
- 期末棚卸資産合計には製造原材料、包装材料、自製酒等、食品材料、商品を含めます。
- 年度確定には、計算エラー0件、人による確認とメモ、全警告の確認理由、確定担当者名が必要です。

詳細は `docs/calculation-spec.md`、Excelとの対応は `docs/excel-mapping.md` を参照してください。

## デモとCSV

正常デモは計算エラー・警告とも0件で、人による確認だけが未完了です。エラー確認用デモには配賦差額、数量差異、負の原価、食品未配賦差額、財務集計対象外副産物の非ゼロ金額を意図的に含めます。どちらへの切替も現在データを上書きするため確認が必要です。

CSVはUTF-8／Shift-JIS判定、ヘッダー正規化、行列数、先頭5行のプレビューまでです。実物CSVの業務上の列対応が確定していないため「原価データへ反映」は無効で、推測による取込は行いません。
